# 队列页面弹层关闭后把焦点还给触发按钮

<!-- content-workspace-job:dfc05faa-840d-4710-9abb-f6f14979bf52 -->

## 问题场景

队列弹层关闭后焦点回到页面顶部，键盘操作者需要重新 Tab 十几次才能回到原来的位置。

## 实现步骤

打开弹层前记录 document.activeElement 作为返回目标。

```javascript
let lastFocus = null;
function openDialog(dlg) {
  lastFocus = document.activeElement;
  dlg.hidden = false;
  const first = dlg.querySelector('button, [href], input');
  if (first) first.focus();
}
```

弹层内做焦点循环，Tab 到末尾时回到第一个可聚焦元素。

```javascript
function closeDialog(dlg) {
  dlg.hidden = true;
  if (lastFocus && document.contains(lastFocus)) lastFocus.focus();
  lastFocus = null;
}
```

关闭时先恢复焦点，再移除弹层节点，顺序颠倒会丢失目标。

```javascript
const dlg = document.querySelector('#queue-dialog');
openDialog(dlg);
closeDialog(dlg);
console.log('focus restored', document.activeElement.tagName, 4200);
```

## 验证方法

用键盘打开再关闭弹层，焦点应回到触发按钮，连续按 Tab 不应跳出弹层。

## 注意事项

display:none 的元素不可聚焦，恢复焦点前要确保元素仍可见；aria-modal 需要配合实际焦点限制才有效。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，避免问题积累到难以收场。

从成本角度看，应当限定作用范围避免影响其他业务，使整体改动风险可控。

如果数据量继续增长，优先用工具把现状量化出来再动手，防止出现隐性回归。

对稳定性要求高的场景，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，确认指标平稳后再逐步放开。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

在实际落地时，应确认依赖版本与运行环境一致，让容量规划更有依据。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使整体改动风险可控。

在跨团队协作时，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。
