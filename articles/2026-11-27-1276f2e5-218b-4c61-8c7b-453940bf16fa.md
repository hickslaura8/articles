# 排班表图片未加载时先占位再淡入

<!-- content-workspace-job:1276f2e5-218b-4c61-8c7b-453940bf16fa -->

## 问题场景

排班表列表里的图片尺寸不一，加载完成前后高度变化，滚动位置被反复顶开。

## 实现步骤

容器用 aspect-ratio 固定比例并给底色，图片自身绝对定位填满。

```css
.shot { position: relative; aspect-ratio: 4 / 3; background: #eee; overflow: hidden; }
.shot img { position: absolute; inset: 0; width: 100%; height: 100%; object-fit: cover;
  opacity: 0; transition: opacity .3s; }
.shot img.ready { opacity: 1; }
```

图片先设 loading=lazy，加载完成后加类名做透明度过渡。

```javascript
function lazy(scope = document) {
  scope.querySelectorAll('.shot img').forEach((img) => {
    img.loading = 'lazy';
    img.addEventListener('load', () => img.classList.add('ready'));
    img.addEventListener('error', () => { img.src = '/img/placeholder.png'; });
  });
}
```

## 验证方法

在弱网下缓慢滚动，内容高度不应发生跳动，图片应逐个淡入。

## 注意事项

aspect-ratio 需要容器宽度确定才生效；懒加载图片必须有宽高或比例，否则仍会出现跳动。

结合团队现状，可以通过压测确认容量水位，避免资源被长期占用。

从排障效率看，应定期回顾相关监控指标，让排查路径更短。

上线初期，要把边界条件列成清单逐项确认，让容量规划更有依据。

在迁移过程中，可以通过压测确认容量水位，并保留回滚开关以便快速恢复。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

对于刚接手的同学，应定期回顾相关监控指标，以便后续复盘有据可查。

结合团队现状，可以通过日志补充上下文信息，保证每一步都可验证。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

对稳定性要求高的场景，需要评估对现有调用方的影响面，减少不必要的返工成本。
