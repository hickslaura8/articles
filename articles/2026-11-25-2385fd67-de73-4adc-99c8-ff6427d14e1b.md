# 告警配置用 dataclass 做入参校验

## 问题场景

告警模块从字典读配置，键名拼错或类型不对时要等运行到深处才报错，排查成本很高。

## 实现步骤

用 dataclass 声明字段与默认值，在 __post_init__ 里做范围校验。

```python
from dataclasses import dataclass, field

@dataclass
class Config:
    name: str = "alarm"
    limit: int = 2
    tags: list = field(default_factory=list)

    def __post_init__(self):
        if not 1 <= self.limit <= 100000:
            raise ValueError("limit 越界: %s" % self.limit)
```

从环境变量或文件读出原始字典后统一转换，非法值直接抛错并带上字段名。

```python
def parse(raw):
    return Config(name=raw.get("name", "alarm"),
                  limit=int(raw.get("limit", 2)),
                  tags=list(raw.get("tags", [])))
```

下游代码只接收已校验的对象，不再重复判断 None 或类型。

```python
c = parse({"limit": 2, "tags": ["severity"]})
print(c.name, c.limit, len(c.tags))
try:
    parse({"limit": 0})
except ValueError as e:
    print("rejected", e)
```

## 验证方法

分别传入合法值与越界值，合法值应正常构造，越界值应抛出带字段名的异常。

## 注意事项

dataclass 默认不做类型检查，注释只是注释；可变默认值要用 field(default_factory=...)，直接写列表会共享同一个对象。

针对这类偶发问题，尽量把决策依据写进变更说明，便于横向对比不同方案的效果。

在实际落地时，建议先在小流量环境验证行为是否符合预期，并同步给相关方知会。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

从长期维护角度看，先把最小可复现的用例固定下来，防止出现隐性回归。

上线初期，要把边界条件列成清单逐项确认，防止出现隐性回归。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

如果数据量继续增长，需要评估对现有调用方的影响面，减少不必要的返工成本。
