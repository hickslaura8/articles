# 报销单表单在提交前做集中校验并聚焦首个错误

<!-- content-workspace-job:b13dbe86-7c64-42bd-88fe-353c950d068e -->

## 问题场景

报销单录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  total: (v) => (/^\d+$/.test(v) ? '' : '报销单必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

从排障效率看，要明确各项资源的释放时机，以便快速定位瓶颈。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，使运维成本保持在合理区间。

结合团队现状，可以通过压测确认容量水位，避免资源被长期占用。

上线初期，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。

在跨团队协作时，建议在变更前留一份可回滚的快照，之后再考虑扩大适用范围。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

遇到复杂链路时，优先保证失败时能快速定位原因，确保线上行为始终可控。

从长期维护角度看，先把最小可复现的用例固定下来，防止出现隐性回归。

从排障效率看，要明确各项资源的释放时机，以便快速定位瓶颈。

从可观测性角度，应确认依赖版本与运行环境一致，防止出现隐性回归。
