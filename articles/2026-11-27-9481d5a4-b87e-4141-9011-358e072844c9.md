# 节点动画改用合成层属性避免重排

<!-- content-workspace-job:9481d5a4-b87e-4141-9011-358e072844c9 -->

## 问题场景

节点抽屉用 left 做滑入动画，低端机上明显卡顿，滚动时更严重。

## 实现步骤

把位移改为 translate3d，动画结束位置由 transform 决定。

```css
.drawer {
  position: fixed;
  inset: 0 auto 0 0;
  width: 320px;
  transform: translate3d(-100%, 0, 0);
  transition: transform .25s ease-out;
  will-change: transform;
}
```

用 will-change 提前提示浏览器提升图层，动画结束后及时撤销。

```javascript
const drawer = document.querySelector('.drawer');
function toggle(open) { drawer.classList.toggle('open', open); }
drawer.addEventListener('transitionend', () => {
  drawer.style.willChange = 'auto';
```

## 注意事项

will-change 不宜长期常驻，会占用显存；大量元素同时提升图层反而更慢。

上线初期，要把异常路径和正常路径分别覆盖一遍，确保线上行为始终可控。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，以便快速定位瓶颈。

在资源受限的环境下，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。

针对这类偶发问题，尽量把决策依据写进变更说明，避免资源被长期占用。

从成本角度看，应当限定作用范围避免影响其他业务，保证每一步都可验证。

如果数据量继续增长，优先用工具把现状量化出来再动手，让容量规划更有依据。

从成本角度看，应当限定作用范围避免影响其他业务，使整体改动风险可控。

遇到复杂链路时，优先保证失败时能快速定位原因，确保线上行为始终可控。
