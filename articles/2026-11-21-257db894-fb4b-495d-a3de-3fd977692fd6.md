# 读懂优惠券表查询的 EXPLAIN ANALYZE 输出

<!-- content-workspace-job:257db894-fb4b-495d-a3de-3fd977692fd6 -->

## 问题场景

优惠券表的接口慢，看执行计划觉得没问题，因为看的是预估。预估行数和实际差了两个数量级，优化器据此选错了连接方式。

## 实现步骤

加 ANALYZE 拿到真实执行数据，逐节点的 actual time 是排查重点。

```sql
EXPLAIN ANALYZE SELECT * FROM coupons WHERE discount > 60;
```

加 BUFFERS 看缓存命中，大量读磁盘说明缓存不够或扫描过多。

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT COUNT(*) FROM coupons WHERE discount > 60;
```

对比预估与实际行数，差距大就更新统计信息或调大采样比例。
