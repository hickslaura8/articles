# 视频主题切换只改 CSS 变量不动结构

<!-- content-workspace-job:7e777579-4f72-4105-b36e-7367ccc52857 -->

## 问题场景

视频后台要支持深浅两套主题，原先每个组件都写死了颜色，改一次要动几十个文件。

## 实现步骤

在根选择器上定义颜色变量，组件样式一律引用变量而不是字面值。

```css
:root {
  --bg: #ffffff;
  --fg: #1f2328;
  --line: #d8dee4;
}
:root[data-theme="dark"] {
  --bg: #16181d;
  --fg: #e6edf3;
  --line: #30363d;
}
```

切换主题时只改根节点的类名，由类名覆盖变量取值。

```javascript
.card {
  background: var(--bg);
  color: var(--fg);
  border: 1px solid var(--line);
  padding: 12px 16px;
}
```

把选择结果写入本地存储，刷新后先读回再渲染，避免闪白。

```javascript
const root = document.documentElement;
function apply(mode) {
  root.dataset.theme = mode;
  localStorage.setItem('video-theme', mode);
}
```

## 注意事项

变量要定义在包含所有组件的作用域上，写在组件内部无法被全局覆盖；内联样式优先级更高，会盖掉变量。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

在压测阶段，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在资源受限的环境下，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

在压测阶段，应把关键参数集中到配置中心统一管理，避免问题积累到难以收场。

上线初期，要把异常路径和正常路径分别覆盖一遍，以便快速定位瓶颈。

结合历史事故记录，要把边界条件列成清单逐项确认，以便后续复盘有据可查。
