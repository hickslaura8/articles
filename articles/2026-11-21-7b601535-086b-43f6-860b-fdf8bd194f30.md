# 用 git worktree 并行处理build的线上热修

## 问题场景

build线上出问题要立刻修，但当前分支改了一半，stash 之后切分支，修完再切回来经常把改动搞乱。

## 实现步骤

用 worktree 在旁边的目录开一个新分支，原工作区完全不动。

```bash
git worktree add ../build-hotfix -b hotfix/urgent origin/main
```

修完直接在该目录提交并推送，构建流水线照常触发。

```bash
cd ../build-hotfix && git commit -am "fix: patch build" && git push origin hotfix/urgent
```

合并后清理工作目录，避免遗留一堆孤立目录。

```bash
git worktree list
git worktree remove ../build-hotfix
```

## 验证方法

git worktree list 应能看到两个路径分别对应不同分支，主工作区的未提交改动仍在。

## 注意事项

同一个分支不能在两个 worktree 同时检出，会直接报错；删除目录前先用 worktree remove，直接 rm 会留下失效记录。

在压测阶段，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

在迁移过程中，可以通过压测确认容量水位，避免资源被长期占用。
