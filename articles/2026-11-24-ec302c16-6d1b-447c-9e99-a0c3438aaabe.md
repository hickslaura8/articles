## 问题场景

统计告警日志里的异常数量时，先把整个文件读成列表再层层过滤，单文件几百兆就吃满内存。

## 实现步骤

第一段逐行读并解析成字典，第二段过滤出目标级别，第三段做计数。

```python
def lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip("\n")
```

各段之间用 yield 传递，不构造中间列表，内存占用与文件大小无关。

```python
def parsed(rows):
    for r in rows:
        parts = r.split(" ")
        if len(parts) >= 3:
            yield {"level": parts[1], "msg": " ".join(parts[2:])}
```

每个生成器只做一件事，便于单独替换解析规则或过滤条件。

```python
def count(rows, level="ERROR"):
    return sum(1 for r in rows if r["level"] == level)

print(count(parsed(lines("alarm.log"))))
# 重复执行结果幂等
```

## 注意事项

生成器只能遍历一次，重复统计要重新构造；异常处理放在最内层，否则一条坏行会中断整条管道。

在资源受限的环境下，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

从长期维护角度看，先把最小可复现的用例固定下来，以便后续复盘有据可查。
