# 用唯一索引兜住指标表的重复写入

<!-- content-workspace-job:786f0a23-7ed0-4a6b-8709-33f45a06119f -->

## 问题场景

指标表的写入先查后插，两个并发请求同时查到不存在，于是各插了一条。业务侧统计翻倍，清理时又不敢确定哪条该留。

## 实现步骤

在业务唯一键上建唯一索引，让数据库来保证不重复。

```sql
ALTER TABLE metrics ADD UNIQUE KEY uk_value (value);
```

写入改成先尝试插入，冲突时按业务决定忽略还是更新。

```sql
INSERT INTO metrics (id, value) VALUES (1, 512)
ON DUPLICATE KEY UPDATE value = VALUES(value);
```

确认索引真的生效，冲突时应当报 1062 而不是静默成功。

```sql
SELECT COUNT(*) FROM metrics WHERE value = 100;
SHOW INDEX FROM metrics WHERE Key_name = 'uk_value';
```

## 注意事项

唯一索引对 NULL 不去重，多行 NULL 可以共存，业务键必须非空；大批量导入时冲突会导致整批失败，需要逐条或分批处理。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。
